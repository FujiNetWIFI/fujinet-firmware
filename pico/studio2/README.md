# pico/studio2

FujiNet for the RCA Studio II: an RP2354B cartridge that serves the console's CDP1802 bus in
software, carries a read-hotspot mailbox to an ESP32-S3 `fujiversal-studio2` over USB CDC, and
serves the CDP1861's display itself.

## How it fits

The mailbox service (`fujimail.c`), FujiBus codec, USB transport and USB device come from
[pico/common/](../common/); the arena offsets are the 5200's.

The ESP32-S3 side is plain `BUILD_RS232` with USB host transport (`fujiversal-studio2`); it
pushes a mounted `.st2`/`.bin` to the cart as DBC frames. The cart plans and stages it, and the
client's `fn_handover` starts the BIOS over: the cart swaps the image in on the BIOS's first
fetch. FujiNet apps are ST2 images with `"FUJI"` at `$07FC`; CONFIG
(`fujinet-config/studio2`) is baked into the firmware and served at power-on.

The edge has no write strobe, so the console reaches the cart only through the address of a
read: a register write is a read of `$E9nn` then `$EAvv`; a TX byte a read of `$EBbb`; text a
read of `$EDcc`. Unlike every earlier cart, the Studio II edge carries the full address of every
read (MA0-7 plus TPA gated by /MRD) and a CART CS line that turns console RAM off, so the cart
claims whole pages anywhere outside the BIOS, including the raster the 1861 fetches by DMA.

## Protocol 2

`FN_PROTO_VER` 2 adds, for apps bigger and busier than CONFIG:

- **Bigger images.** An ST2 may name 192 blocks, its header's whole page map: every legal page
  (~41K) at once. `$C400-$CFFF` is a bank window: each block naming `$C4` after the first opens
  the next bank, and a read of `$E980+n` puts bank n there from the next fetch (core1 decodes
  it; CLEAR and the swap bring back bank 0). A page a bank lacks reads `$FF`. `build.sh` builds
  a banked client from one source assembled once per bank (`; BANKS: n`, `-D BANK=k`).
- **Writable pages.** Every page a block backs can be written: registers `$18`/`$19` set a
  pointer, and after `$1A` each REGDATA stores a byte there and advances it (core1, at once).
  COPY (`$1B-$20`: source, destination, length; the length's high byte runs it) copies the
  reply window or image bytes on core0, and `FN_R_COPYDONE` counts the COPYs done.
- **Drawing while a transaction is out.** The FujiBus transports call an idle hook while they
  wait; the cart draws what the console sent after the transaction's launch, up to the next
  mailbox read.
- **Graphics.** Images up to 8x24 stamped at any pixel, rectangles with patterns, text at any
  pixel, 16 sprites and a whole-picture offset/inversion (`S2T_OP_IMAGE`-`S2T_OP_PTEXT`). The
  1861 is shown the background (cells, stamps, rectangles) with the VIEW and the sprites
  composed into a second buffer, taken at the start of a frame, so a picture never tears.

## Build

```sh
./build.sh                          # 1802 clients -> build/*.st2 (needs ~/asl/asl)
./build-cart.sh [--baked|--bake]    # RP2354B firmware -> build/fw-*/fujistudio2.uf2
make -C firmware/host_test          # host tests
emu/apply.sh ~/Workspace/mame-studio2   # graft the device, then build MAME:
#   make SUBTARGET=studio2 SOURCES=src/mame/rca/studio2.cpp REGENIE=1 NOWERROR=1
./run.sh fujitest fttest            # a client in MAME, headless, against fujinet-pc
```

`run.sh` talks to a fujinet-pc on `$FUJINET_TCP` (default `127.0.0.1:9997`); its BoIP port takes
one client at a time. Not built by `build_pico.py` or the ESP32 build yet.

## Notes

Rules every client keeps (the includes enforce them; `checkrom.py` checks the listing):

- Registers: R0 DMA (the ISR's), R1 ISR, R2 stack, R3 PC, R4/R5/R7 call/return/jump, R6 link,
  R8-R9 scratch, RA-RC preserved, RD.0 beep frames, RE frames, RF the hotspot pointer.
- No 3-cycle opcode (`LBR`, long skips, `NOP`): one in flight when the 1861 asks for DMA costs
  that line a byte. Leave a page with `FJMP` or `FCALL`; precede every routine with a short
  branch by `FIT n` so it does not straddle a page.
- RF is read only with `LDN` and parked on page `$0B` between uses; nothing stores through it or
  makes it X. `OUT` reads M(R(X)): keep X on console RAM.
- The runtime fills `$0400-$07FB`; client code starts at `$0C00`, then `$x400-$xFFF` for
  x = 1..D (`$C400-$CFFF` banked). Never `$x000-$x3FF` (the BIOS ROMs may mirror there),
  `$08-$09`, `$0B`, or `$E4` up. Never store into the cart's pages: with no write strobe on
  the edge, a store lands in a console-RAM mirror.
- Assemble with `-U`: AS is case-insensitive otherwise, and `fn_frames` is not `FN_FRAMES`.

Emulation results (MAME, `tools/abrun.py`, `tools/tierb.py`, against `/tmp/studio2`, 14 TOSEC
files, and `tools/mkcorpus.py`'s 7 synthetic layouts):

| Tier | Result |
|---|---|
| A, frame equality vs MAME's cart | 13/13 games equal; the 2K BIOS dump refused by both; synthetic: 1 equal, 6 differ by design (MAME's uninitialized buffer, pages it never maps, its sub-`$04` misalignment) |
| B, state at the game's first `$0400` | 13/13 equal to a power-on (registers the BIOS sets, all RAM but the beep timer and below its stack) |
| C, the network path (`tools/soak.py`) | 13/13: pushed from fujinet-pc, handed over, view byte-equal to `s2plan`, game on screen |
| `test_cycles` | fujitest and fujiboot traces: every read the chip makes and MAME does not lands on a page with no side effect; the transactions replay as logged |
| CONFIG (`fujinet-config/studio2`, `emu/cfgtest.lua`) | baked, from power-on: hosts, browse and page `/studio2/`, a scrolling name, boot; rename through the keyboard; WiFi, info, copy, a refused image; `CFG_EXTRA=3` boots 5 Card Stud and quits back to CONFIG |
| 5 Card Stud (`fujinet-5cardstud/studio2`, `emu/5carddrive.lua`) | name, live lobby on `5card.carr-designs.com`, two hands played, back to CONFIG |

MAME quirks the harnesses work around: the 1802 core never runs its reset at power-on (IE stays
0 until CLEAR), so the Tier B reference pulses CLEAR as the console's RC reset would; a soft
reset resets the cart and the 1861 but not the CPU, so `powertest` adds CLEAR; Lua must read the
device's save items, never the address space (a read there fires hotspots); a tap set before the
device's reset is removed by it.

CDP1802A Table 2 settles one hardware question: non-memory execute cycles (GLO, PLO, INC, SEX,
...) have MRD = 1, so the console's TPA gate never shows them to the cart. The chip does read
where MAME does not -- a short branch's operand taken or not, IRX at R(X), IDL at R0 -- which is
why clients may not use IDL and why `test_cycles` checks the rest.

No hardware exists. Open questions for the first board (one session): whether the BIOS ROMs
mirror above `$1000` (`fujitest` row 8 probes it), the gated-TPA width and low-byte settle time
(`S2_LO_DELAY_NS`), whether a 3-cycle opcode shortens a real 1861 burst, the power-on race (the
BIOS reaches `$0400` about 50 ms after power-on), and CART CS contention timing.
