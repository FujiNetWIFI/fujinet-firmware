# pico/sms

FujiNet for the Sega Master System: an RP2354B cartridge with 1 MB of SRAM that serves CONFIG and
a memory-mapped mailbox, loads any image the ESP32-S3 pushes into the SRAM, and runs it there.

## Layout
| Path | Defines |
|---|---|
| `firmware/include/fuji_mailbox.h` | the mailbox: arena at `$B000`, status fields, registers, loader protocol, the claim |

| `firmware/include/smsmap.h`, `firmware/src/smsmap.c` | the mapper engine: which 8K SRAM bank sits behind each 1K page; plan an image (CRC database, `.cfg` override, MAME's heuristic) |

| `firmware/include/fuji_load.h`, `firmware/src/fuji_load.c` | the load sequence: staged image into the SRAM one 8K window at a time, then the hand-over |
| `firmware/src/sms_cart.c` | core1: bank bits on every address change, cart-served reads, write dispatch |
| `firmware/src/fuji_cart.c` | core0: the ring drain, the load sequence's port, the console watchdog |

## How it fits
- The console addresses the SRAM itself: A0-A12 and D0-D7 go straight to it. core1 supplies
  A13-A19 from the live mapper's page table, and 74HCT gates decide who drives D from the address
  and four mode bits (`GAME`, `MBOX`, `RAM_WE`, `LOAD`), so no software sits in an enable path.
- RESIDENT: CONFIG is served by the cart at `$0000-$7FFF`. GAME: a pushed image runs from the SRAM.
  APP: a pushed image that carries the claim also keeps the arena at `$B000-$BFFF`, over the top
  4K of slot 2 in every bank; apps may be up to 1 MB.
- A push lands in `fuji_store` inside MOUNT_IMAGE, as on every sibling. The client then jumps to the
  loader page, which reads each 8K window at `$8000` while the SRAM latches the bytes the cart
  drives, restores what the BIOS left (snooped at power-on), and jumps to `$0000`; the cart flips
  on that fetch.
- The ESP32 side is the `fujiversal-sms` board ([lib/bus/rs232/](../../lib/bus/rs232/) over USB CDC).

## Build
- `./build.sh` assembles the loader and builds the clients into `build/` (z88dk at
  `~/Workspace/z88dk`, `Z88DK` overrides). `./build-cart.sh` bakes a client (`build/config.sms`
  from fujinet-config `sms/` if present) and the loader into `build/gen` and builds the firmware;
  `--baked` builds from `firmware/baked/` alone, `--bake` refreshes it.
- `make -C firmware/host_test` runs the host tests.
- `emu/apply.sh ~/Workspace/mame`, then `make REGENIE=1 NOWERROR=1` in the MAME tree, grafts the
  device (`-slot fujinet`) and adds a `none` BIOS to the export consoles. `./run.sh` runs a client;
  `./run.sh config cfgtest` drives the real CONFIG (fujinet-config `sms/`, `make install`).

## Notes
- Edge (export SMS, 50 pins): A0-A15, D0-D7, `/RD`, `/WR`, `/MREQ`, `/IORQ`, `/M1`, `/CE` (that is
  `/MREQ` gated by port `$3E`, with no address), `/RESET` (power-on), `CLK`, `/WAIT`. The 44-pin
  Japanese and Mark III edge is not supported.
- The BIOS writes `$C000` with the cart disabled, so the snoop keys on `/MREQ`, not `/CE`.
- Mappers: Sega, Codemasters, Korean, Korean no-bank, Zemina, Nemesis, Janggun (whose bit-reversed
  banks are a second copy in the SRAM) and 4 PAK, each matching MAME's `sega8` device byte for
  byte. Korean multicarts are not supported.
- The loader restores what the BIOS left: `$C000`, ports `$3E`/`$3F`, VDP R0-R10 and the `$DFFC`
  mirror. An image with no Sega header, which no export BIOS boots, gets RAM filled with `$F0`
  and power-on VDP registers instead, as on the Japanese and Korean consoles it was made for.
- Tier A (`tools/abrun.py`): every image in the corpus on MAME's own cart and on this one, same
  console and inputs, snapshots every 2 s for 60 s. Tier C (`tools/soak.py`): every image through
  BIOS, CONFIG's boot path, the push and the loader, with the SRAM checked byte for byte.
- Alocos (Taiwan) writes 0 to port `$3E`, which switches the console's BIOS back on over the
  cart, so it runs only on a console without one. The bare BIOS dumps behave as on MAME's own
  cart with no BIOS.
- The board is a Rev0 schematic (fujinet-hardware `SMS/FujiNet-SMS-Rev0`), not yet built;
  everything here ran in host tests and MAME only.
