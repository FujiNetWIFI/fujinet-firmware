# pico/s100

FujiNet for S-100 machines: an RP2354B on an S-100 card that answers a FujiBus pipe, an Altair
FDC+-compatible floppy controller, an 88-2SIO-compatible serial pair and a boot page, and relays
them over USB CDC to an ESP32-S3 `fujiversal-s100` on the same card.

## Layout

| Path | Defines |
|---|---|
| `firmware/include/s100_card.h` | Block codes, DIP defaults, the RP2354B pin map, and the pipe registers (GETC, STATUS, PUTC, CONTROL/TICK), LOAD header and card info block |
| `firmware/include/s100_glue.h` | The decode and wait-state glue as equations: '688 block decode, the ARM flip-flop on pSYNC, PRDY*, DI enable, PHANTOM* |
| `firmware/include/s100_regs.h`, `src/s100_regs.c` | The card: register dispatch for every block, the boot page and its patching, POJ, LOAD |
| `firmware/include/s100_fdc.h`, `src/s100_fdc.c` | The FDC+ engine in its serial-drive model: 8", minidisk and 8 MB drives backed by FujiNet slots, a track cache filled one 137-byte sector per FujiBus read |
| `firmware/include/s100_2sio.h`, `src/s100_2sio.c` | Two 6850s: channel A the FujiNet modem, channel B the printer |
| `firmware/include/s100_link.h`, `src/s100_link.c` | The USB link mux: host frames, FDC sector traffic, printer and modem on one CDC channel, one request at a time |
| `firmware/include/s100_ring.h` | Single-producer rings between the bus side and the link side |
| `firmware/src/s100_bus.pio`, `src/main.c` | The held-cycle handshake in PIO; core1 answers cycles from SRAM, core0 runs USB and the link |
| `firmware/boards/` | `fujis100_rp2354b` board for the pico-sdk |
| `firmware/baked/` | The boot page and the images (CONFIG, the loader) the card serves, generated by `build-cart.sh --bake` |
| `firmware/host_test/` | `test_regs`, `test_2sio`, `test_fdc` (Altair-style read and write sequences), `test_link` (against `fake_esp.h`), `test_glue`, `test_timing` (IEEE-696 budgets), `test_pio` (the PIO program on a model) |
| `client/` | 8080 sources (z88dk-z80asm `-m8080`): `bootpage` (the 256-byte page), `loader` (a DBL-compatible boot loader), `fnhello`, `fntest`, `mdmtest`, `prntest`, `fnbios` with `fnbres` (CP/M devices and drives), `bootcheck` (a stand-in image 0), and their includes |
| `emu/` | The SIMH AltairZ80 device (`s100_fujinet.c`), `apply.sh`, and the scenarios `run.sh` drives |
| `tools/` | `mkpage.py` (the boot page's patch sites, the image headers), `fujibus.py` with `dskcheck.py` and `fnmount.py` (BoIP clients), `fetch-disks.sh` (deramp images, MDBL, a blank 8 MB image) |
| `build.sh`, `build-cart.sh`, `run.sh` | The clients and generated headers; the RP2354B firmware; a scenario in SIMH against fujinet-pc |

## How it fits

The ESP32-S3 side is plain `BUILD_RS232` with USB host transport; Altair `.dsk` images mount as
`MediaTypeAltair` (lib/media/rs232/), 137-byte sectors addressed by track and sector. The card
decodes four blocks from DIP switches, holds each of its cycles with PRDY until the RP answers,
and so meets the bus at any CPU speed:

- the pipe (four ports, A0h by default) carries FujiBus/SLIP from S-100 software, which is what
  fujinet-lib's `bus/s100` and CONFIG use;
- the FDC+ at 08h-0Ah runs the Altair DBL, MDBL, CP/M, Altair DOS and Disk BASIC from FujiNet
  slots 1-8 as drives 0-7;
- the 2SIO (14h by default) gives unmodified software the FujiNet modem and printer;
- the boot page (FF00h by default) streams CONFIG from the card's flash into RAM at 0100h, and
  its second entry streams the loader that boots drive 0, so no OS is needed to mount images.

Images carrying `"FNS1"` get the card's settings (pipe base, page, console, PHANTOM, drive 0
geometry) filled in as they stream.

## Build

```sh
./build.sh                          # 8080 clients, boot page, images -> build/client, build/gen
                                    # (needs ~/Workspace/z88dk; FUJI_CONFIG=CONFIG.BIN for image 0)
./build-cart.sh [--baked|--bake]    # RP2354B firmware -> build/fw-*/fujis100.uf2
make -C firmware/host_test          # host tests
tools/fetch-disks.sh                # deramp minidisk/8 MB images, MDBL, a blank 8 MB image
emu/apply.sh ~/Workspace/simh-s100  # graft the card into SIMH, then: make altairz80
./run.sh burcon [--cpu z80 --mhz 4] [--async] [--native]
```

`run.sh` talks to a fujinet-pc on `$FUJINET_TCP` (default `127.0.0.1:1995`) whose BoIP port takes
one client at a time, and boots MITS images from z80pack's library with the DBL from z80pack's
`roms/`. Not built by `build_pico.py` or the ESP32 build yet.

## Notes

- All S-100 code is 8080 code, so it runs on an Altair or IMSAI as well as a Z80 card.
- The FDC+ timing is the serial-drive model: only sector cadence and step delay are real time,
  and sector data is there the moment the CPU reads it.
- Bus timing is checked only by `test_timing` against datasheet numbers; SIMH has none.
